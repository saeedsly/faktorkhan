# فاکتورخوان — OCR فارسی (سرور محلی روی CPU + سیستم تست دقت)

این بخش دو موتور دارد:

1. **سرور محلی (پیشنهادی):** PP-OCRv5 با مدل عربی/فارسی `arabic_PP-OCRv5_mobile_rec` از PaddleOCR، اجرا با ONNX Runtime روی CPU. وزن‌ها را خودتان از Hugging Face دانلود می‌کنید و روی همان رایانه اجرا می‌شوند؛ فایل فاکتور به هیچ سرور خارجی فرستاده نمی‌شود.
2. **داخل مرورگر (پشتیبان):** Tesseract.js با داده‌ی `fas`. دقت ارقام آن کم است (نتایج در `eval/report-tesseract.json`) و فقط برای وقتی است که سرور محلی راه‌اندازی نشده باشد.

> **وضعیت دقت:** در محیط توسعه‌ی من مدل‌های PP-OCRv5 و PaddleOCR-VL قابل دانلود نبودند، پس **دقت آن‌ها هنوز اندازه‌گیری نشده است**. اعداد واقعی را با دستورهای زیر روی رایانه‌ی خودتان و با `eval` می‌گیرید. گزارش Tesseract موجود است.

## ۰. نصب یک‌کلیکی روی ویندوز (پیشنهادی)

1. Python 3.11 (۶۴ بیتی) را از python.org نصب کنید و گزینه‌ی «Add python.exe to PATH» را بزنید.
2. پوشه‌ی `ocr` را از مخزن دانلود کنید (ZIP یا `git clone`).
3. روی `ocr\windows\install.bat` دوبار کلیک کنید. این فایل محیط Python را می‌سازد، وابستگی‌ها و مدل‌های PP-OCRv5 را نصب می‌کند.
4. اگر می‌خواهید موتور دست‌نویس (Qwen) را هم داشته باشید، در مرحله‌ی آخر سه مسیر را وارد کنید:
   - پوشه‌ای که `llama-server.exe` در آن است،
   - فایل مدل `.gguf`،
   - فایل `mmproj-*.gguf` (بدون آن، مدل تصویر را نمی‌بیند).
   اگر این‌ها را ندارید، خالی بگذارید؛ موتور چاپی کار می‌کند.
5. برای اجرا روی `ocr\windows\start.bat` دوبار کلیک کنید؛ مرورگر باز می‌شود. دو پنجره‌ی سرور را باز نگه دارید.

تنظیمات مسیرهای Qwen در `ocr\windows\config.bat` ذخیره می‌شوند و در Git نیستند. اگر فایل‌های مدل را جابه‌جا کردید، `install.bat` را دوباره اجرا کنید.

> این فایل‌ها روی ویندوز ۱۰ نوشته شده‌اند ولی در محیط توسعه‌ی من (لینوکس) اجرا نشده‌اند؛ اگر خطایی دیدید، متن پنجره را بفرستید.

## ۱. نصب (Windows یا Linux، بدون GPU)

از پوشه‌ی `ocr/` (Python 3.10 یا بالاتر؛ در محیط آزمایش من فقط Python 3.11 تست شده است):

```bash
python -m venv .venv
.venv\Scripts\activate            # در Linux: source .venv/bin/activate
pip install -r requirements-server.txt
```

## ۲. دانلود مدل‌ها از Hugging Face

```bash
python scripts/download_models.py
```

یا دستی:

```bash
huggingface-cli download PaddlePaddle/PP-OCRv5_mobile_det_onnx --local-dir models/det
huggingface-cli download PaddlePaddle/arabic_PP-OCRv5_mobile_rec_onnx --local-dir models/rec
```

بعد بررسی کنید که هر پوشه دقیقاً **یک** فایل `.onnx` داشته باشد و موتور بالا بیاید:

```bash
python -m server --models models --check
```

دیکشنری کاراکترها (`server/dict/ppocrv5_arabic_dict.txt`، ۷۴۷ خط، از مخزن PaddleOCR) همراه برنامه است و شامل حروف فارسی `پ چ ژ ک گ` و ارقام `۰–۹` و `0–9` است.

## ۳. اجرا

```bash
python -m server --models models --port 8000
```

سپس در مرورگر: `http://localhost:8000` (اگر از شبکه‌ی دیگری باز می‌کنید، IP رایانه را به‌جای localhost بگذارید؛ سرور روی `0.0.0.0` گوش می‌دهد).

- `--decode paddle` (پیش‌فرض): معکوس‌سازی ترتیب مانند PaddleOCR.
- `--decode raw`: بدون معکوس‌سازی.

رابط کاربری هر دو حالت را نشان می‌دهد (بخش «حالت دیگر معکوس‌سازی»)، چون این تصمیم روی ارقام فارسی اثر دارد (بخش محدودیت‌ها).

اگر وزن‌ها پیدا نشوند، سرور بالا می‌آید، دلیل را در `/api/health` می‌گوید و رابط به موتور مرورگر برمی‌گردد.

### گزینه‌های اختیاری

**تشخیص‌دهنده‌ی PP-OCRv6** (جدیدتر، Apache-2.0؛ مقایسه با v5 در eval):

```bash
python scripts/download_models.py --only-v6 --det-v6 small   # یا medium
python -m server --models models --det-version v6 --port 8000
```

**Qwen3-VL برای دست‌نویس** (روی CPU کند است؛ مدل و mmproj را از Hugging Face بگیرید):

```bash
llama-server -m Qwen3-VL-8B-Instruct-Q4_K_M.gguf --mmproj mmproj-F16.gguf --port 8080
python -m server --models models --vlm-url http://127.0.0.1:8080 --port 8000
```

در رابط، گزینه‌ی «Qwen3-VL» فقط وقتی ظاهر می‌شود که llama-server در دسترس باشد.

مقایسه‌ی موتورها و منابع: `RESEARCH.md`.

## ۴. سیستم تست دقت

### ۴.۱ نمونه‌های ساختگی (از ریشه‌ی ریپو، نیاز به وابستگی‌های faktorkhan)

```bash
python ocr/eval/generate_samples.py 30
```

۳۰ فاکتور با جواب درست ساخته می‌شود (`eval/samples/`، که در Git نیست). فاکتورها با همان سرویس و قالب برنامه ساخته می‌شوند، پس جمع‌ها و تاریخ‌ها دقیق‌اند. فونت رندر را سیستم‌عامل انتخاب می‌کند، پس نمونه‌ها واقعی نیستند؛ نمونه‌های واقعی را بعداً اضافه کنید.

**محدودیت مهم مجموعه‌ی فعلی:** هر ۳۰ نمونه از نوع «دستی» (`MANUAL`) و **چاپی (با فونت)** هستند. نمونه‌ی «سیستمی» و **دست‌نویس واقعی** در این مجموعه نیست، پس این اعداد دقت خواندن دست‌نویس را نشان نمی‌دهند.

### ۴.۲ اجرای تست

```bash
cd ocr
node eval/run_eval.mjs --server http://127.0.0.1:8000 --decode paddle
node eval/run_eval.mjs --server http://127.0.0.1:8000 --decode raw
node eval/run_eval.mjs --server http://127.0.0.1:8000 --engine vlm   # Qwen3-VL (اگر --vlm-url داده شده)
node eval/run_eval.mjs                    # موتور Tesseract (بدون سرور)
```

(Node 18 یا بالاتر لازم است. برای Tesseract یک بار `npm install` در پوشه‌ی `ocr/` بزنید.)

کنترل‌های بیشتر:

```bash
node eval/run_eval.mjs --tess-model 4.0.0                 # مدل float به‌جای best_int
node eval/run_eval.mjs --from-cache tesseract             # بدون OCR دوباره؛ از eval/out/<موتور>/*.txt
node eval/sweep_repair.mjs tesseract tesseract-4.0.0      # مقایسه‌ی پیکربندی‌های تصحیح حسابی
node --test tests/repair.test.mjs                         # تست‌های تصحیح و جداکننده‌ها (در پوشه‌ی ocr/)
```

متن خام OCR هر نمونه در `eval/out/<موتور>/` ذخیره می‌شود (در Git نیست).

گزارش در `eval/report-<موتور>.json` ذخیره می‌شود. معیارها:

- **دقت هر فیلد** (شماره، تاریخ، جمع اقلام، تخفیف، مشمول مالیات، مالیات، مبلغ قابل پرداخت)
- **دقت کامل فاکتور**: همه‌ی فیلدها درست
- **بازیابی عددها**: چند درصد عددهای واقعی فاکتور در متن OCR پیدا شد
- **بازیابی نام کالاها**
- **نرخ تشخیص خطا**: از فاکتورهایی که OCR غلط خوانده، چند درصد توسط بررسی‌های حسابی علامت خوردند
- **تعداد هشدار اشتباه** بررسی‌های حسابی روی فاکتورهای درست
- **عددهای جاافتاده**: فهرست عددهایی که در بیشترین نمونه‌ها خوانده نشدند و در هر نمونه (`per_sample.missing_numbers`)

### ۴.۳ نتایج Tesseract روی ۳۰ نمونه‌ی چاپی-دستی (گزارش‌ها در `eval/report-*.json`)

| معیار | `4.0.0_best_int` (انتخاب شده) | `4.0.0` (float) |
|---|---|---|
| دقت تاریخ | 100٪ | 100٪ |
| دقت جمع اقلام / تخفیف / مشمول / مالیات / قابل پرداخت | 10٪ / 36.7٪ / 3.3٪ / 13.3٪ / 0٪ | همان |
| دقت کامل فاکتور | 0٪ | 0٪ |
| بازیابی عددها | 13.2٪ | 12.9٪ |
| نرخ تشخیص خطا | 100٪ | 100٪ |
| هشدار اشتباه | 0 | 0 |

انتخاب `best_int` بر اساس همین گزارش‌ها است؛ دقت فیلدها برابر و بازیابی عدد کمی بیشتر است.

**نتیجه: Tesseract برای ارقام فاکتور کافی نیست.** بیشتر خطاها حذف/درج رقم یا خوانده‌شدن جداکننده‌ی هزارگان به‌جای رقم است (میانگین حدود ۱۰ ویرایش رقمی در هر فاکتور). ابزارهای زیر را اضافه کردیم:

- **حذف جداکننده‌ی هزارگان خراب** (`stripThousandsNoise`): `۱۷/۵۸۹/۰۰۰` → `17589000`. دقت جمع اقلام را از ۰ به ۱۰٪ و بازیابی عدد را از ۱۱٫۴ به ۱۳٫۲٪ رساند.
- **تصحیح حسابی** (`repairFields`): فقط وقتی تغییری می‌دهد که راه‌حل کم‌هزینه (حداکثر ۲ ویرایش یک‌رقمی) یکتا باشد؛ در غیر این صورت ابهام را گزارش می‌کند. روی این ۳۰ نمونه **هیچ تصحیحی انجام نشد** (نه درست، نه غلط)، چون خطاها بیش از بودجه‌اند. این تصحیح فقط برای موتورهای دقیق‌تر (مثلاً PP-OCRv5) ممکن است مفید باشد که هنوز اندازه‌گیری نشده است.

## ۵. منطق بررسی‌ها

- `public/extract.js`: استخراج فیلدها، بررسی‌های حسابی و تصحیح حسابی؛ هم در مرورگر و هم در تست استفاده می‌شود.
- تصحیح حسابی هر تغییر را در فهرست «تغییرات خودکار» نشان می‌دهد (عدد قبلی و جدید)؛ مقادیر محاسبه‌شده (از معادله‌ی قطعی) هم جدا علامت می‌خورند.
- بررسی‌ها: `جمع اقلام − تخفیف = مشمول مالیات` و `مشمول مالیات + مالیات = قابل پرداخت` و `مالیات ≈ ۹٪`.
  اگر OCR یک رقم را غلط بخواند، معمولاً یکی از این بررسی‌ها شکست می‌خورد و فاکتور برای بازبینی علامت می‌خورد. این بررسی‌ها خطا را **پنهان نمی‌کنند**؛ فقط آن را علامت می‌زنند.

## ۶. محدودیت‌های شناخته‌شده

- **منابع متضاد درباره‌ی ترتیب:** پروژه‌ی Persian-OCR-App ادعا می‌کند خروجی PP-OCRv5 عربی از قبل منطقی است و نباید معکوس شود. کد PaddleOCR برای دیکشنری‌های عربی معکوس می‌کند. این را فقط eval روی نمونه‌ها حل می‌کند.
- **معکوس‌سازی ارقام فارسی:** کد PaddleOCR برای دیکشنری‌های عربی، متن را برمی‌گرداند؛ قطعه‌های لاتین و ارقام ASCII را نگه می‌دارد ولی هر رقم فارسی را جدا معکوس می‌کند. یعنی `۱۲۳` ممکن است `۳۲۱` شود، اگر مدل خروجی را در ترتیب بصری بدهد. این را فقط با اندازه‌گیری روی نمونه‌ها می‌شود فهمید؛ دو حالت `paddle` و `raw` را مقایسه کنید.
- **جدول‌ها:** PP-OCRv5 متن را خط‌به‌خط می‌خواند و ساختار جدول را حفظ نمی‌کند. فیلدها از روی برچسب‌ها و نزدیک‌ترین عدد استخراج می‌شوند؛ جدول‌های پیچیده ممکن است جابه‌جا شوند.
- **دست‌نویس:** PP-OCRv5 برای متن چاپی بهینه است؛ دست‌نویس را فقط با نمونه‌ی واقعی می‌توان سنجید. این مرحله هنوز انجام نشده است.
- **PaddleOCR-VL-1.6:** مدل قوی‌تری است، اما توسعه‌دهندگان آن می‌گویند روی CPU پشتیبانی نمی‌شود و کند است. فعلاً پیاده‌سازی نشده است.
- **PDF:** فعلاً فقط تصویر (JPG، PNG، WebP) پذیرفته می‌شود.
