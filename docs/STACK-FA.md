# فاکتورخوان از چه چیزی ساخته شده؟ (بررسی فنی کامل)

این سند پاسخ روشن به یک سؤال است: **پشت این برنامه چه فناوری‌هایی است و هر کدام چه کاری می‌کنند؟**
هیچ نامی از شرکت ارائه‌دهندهٔ سرویس ابری در این سند نیست (قاعدهٔ محصول).

---

## ۱. خلاصه در یک جدول

| لایه | فناوری | نسخه | نقش |
|---|---|---|---|
| **نسخهٔ WAMP/htdocs** (جدیدترین) | PHP خالص | ۷.۴ تا ۸.۴ | کل برنامه: آپلود، صف، ارتباط با سرویس ابری، خواندن Word |
| **نسخهٔ کامل** (سرور/دسکتاپ) | Python + FastAPI | ۳.۱۱+ | برنامهٔ کامل با کاربر، اشتراک، فاکتورها |
| **پایگاه داده (نسخهٔ کامل)** | SQLAlchemy + MySQL/MariaDB یا SQLite | ۲.۰ | ذخیرهٔ کاربر، فاکتور، کار، لاگ |
| **رابط کاربری** | HTML + CSS + JavaScript خالص | ES5/ES2015 | بدون React، بدون Vue، بدون build |
| **موتور OCR** | سرویس ابری (از طریق درگاه HTTPS) | — | خوانش متن از عکس و PDF |
| **OCR جایگزین (اختیاری)** | Tesseract + pypdf | لوکال | وقتی اینترنت نیست یا کاربر بخواهد |
| **ساخت Word/TXT** | کد PHP خودمان (ZIP + deflate دستی) | — | متن را از فایل سرویس بیرون می‌کشد و Word سالم می‌سازد |
| **نسخهٔ دسکتاپ** | pywebview + PyInstaller | ۵+ | پنجرهٔ بومی ویندوز |
| **استقرار سرور** | Docker + nginx + gunicorn | — | اجرای چندکاربره |

نکتهٔ مهم: **هیچ فریم‌ورک جاوااسکریپتی، هیچ CDN، و هیچ فونت اینترنتی در کار نیست.**
همهٔ کد (۳٬۵۰۹ خط PHP، ۵٬۲۶۳ خط Python، ۳٬۲۶۷ خط JS) داخل خود مخزن است.

## ۲. نسخه‌ای که شما استفاده می‌کنید: PHP خالص

این نسخه عمداً **بدون هیچ وابستگی** نوشته شده تا روی ویندوز ۷ با WAMP یا XAMPP کار کند.

### فایل‌ها و نقش هر کدام

| فایل | خط | کار |
|---|---|---|
| `index.php` | ۱٬۰۳۷ | صفحه + رابط کاربری + API (`api=start`, `api=job`, `api=cancel`, `api=file`) |
| `lib.php` | ۱٬۶۶۷ | هسته: پیکربندی، نشست، امنیت، درگاه، صف کارها، استخراج متن Word |
| `server.php` | ۷۳ | سرور داخلی PHP وقتی Apache دردسر می‌دهد |
| `diag.php` | ۴۶۲ | عیب‌یابی: کل مسیر سرویس ابری را یک‌بار واقعاً طی می‌کند |
| `check.php` | ۱۶۶ | بررسی نیازمندی‌های سرور (curl، دسترسی نوشتن، نسخه) |
| `.htaccess` | ۶۰ | محافظت از فایل‌های حساس (سازگار با Apache 2.2 و 2.4) |

### چه چیزی از PHP استفاده می‌شود؟

فقط افزونه‌های **پیش‌فرض** PHP:

- `curl` — ارتباط با سرویس ابری (تنها افزونهٔ واقعاً لازم)
- `json` — خواندن/نوشتن پاسخ‌ها و پروندهٔ کارها
- `session` — ورود و نگه‌داشتن کارها
- `mbstring` — اختیاری (اگر نباشد، شمارش نویسه را مرورگر انجام می‌دهد)

**عمداً استفاده نشده:** Composer، هیچ پکیج بیرونی، `ZipArchive`، `zlib`.
خواندن ZIP و باز کردن فشرده‌سازی deflate دستی پیاده شده (`fk_inflate_raw`، `fk_zip_entry`)
تا روی هاست‌های قدیمی که این افزونه‌ها را ندارند هم کار کند.

### صف کارها (چرا صفحه قفل نمی‌شود)

هر فایل یک «کار» (`job`) در `fk-jobs/*.json` می‌شود. مرورگر هر ۱.۵ تا ۵ ثانیه
`api=job` می‌زند و سرور **فقط یک قدم کوتاه** برمی‌دارد:

```
addfile  →  convert  →  download  →  done
   ↓          ↓            ↓
۹۰ ثانیه   ۴۵ ثانیه     ۱۸۰ ثانیه   (سقف هر فراخوانی)
```

هیچ درخواستی منتظر پایان OCR نمی‌ماند. سرور داخلی PHP تک‌رشته‌ای است؛ اگر یک
درخواست دقیقه‌ها طول بکشد، کل سایت قفل می‌شود — این طراحی همان مشکل را حل می‌کند.

### ارتباط با سرویس ابری

پروتکل ساده و متنی است (HTTP POST، فرم/مولتی‌پارت، پاسخ JSON):

| دستور | ورودی | خروجی |
|---|---|---|
| `checkcredit` | — | اعتبار OCR (تعداد صفحه) و صوت (ثانیه) |
| `addfile` | فایل (`filehandle`) | `FileToken`، `PageCount`، `ConvertMethods` |
| `convert` | `filetoken`، `method`، `output` | لینک فایل خروجی |
| `checkconvert` | `filetoken` | درصد پیشرفت + متن (فقط صوتی) |
| `cancelconvert` | `filetoken` | توقف تبدیل |
| `deletefile` | `filetoken` | حذف از سرور ابری |

آدرس درگاه **مبهم‌سازی شده** است: Base64 + XOR با کلید `0x5A`، داخل خود `lib.php`.
در رابط کاربری فقط «آماده» یا «نامعتبر» دیده می‌شود، هیچ‌وقت URL.
توکن هم فقط در `fk-config.json` است و در صفحه به شکل `ABCD…WXYZ` نشان داده می‌شود.

### خواندن فایل Word بدون هیچ افزونه‌ای

فایل `.docx` در واقع یک بستهٔ ZIP است که متن در `word/document.xml` دارد.
برنامه:

1. فهرست مرکزی ZIP را می‌خواند (`PK\x01\x02`) و `word/document.xml` را پیدا می‌کند
2. اگر فایل فشرده باشد، **inflate دستی** (جدول هافمن ثابت و پویا، RFC 1951) باز می‌کند
3. XML را به متن تبدیل می‌کند: `</w:p>` → خط جدید، `</w:tc>` → تب (برای اکسل)
4. اگر بستهٔ سرویس معتبر نبود، خودش یک `.docx` کمینه و استاندارد می‌سازد

## ۳. نسخهٔ کامل (پایتون) — وقتی چند کاربر و اشتراک لازم است

معماری سه‌لایه:

```
مرورگر  →  FastAPI (Python)  →  SQLAlchemy  →  MySQL / MariaDB / SQLite
                    ↓
              سرویس ابری OCR  (یا Tesseract محلی)
```

### کتابخانه‌های پایتون و دلیل هر کدام

| کتابخانه | نسخه | چرا |
|---|---|---|
| `fastapi` | ۰.۱۶۲ | فریم‌ورک API؛ خودکار Swagger در `/api/docs` |
| `uvicorn` | ۰.۵۴ | سرور ASGI |
| `SQLAlchemy` | ۲.۱ | ORM؛ همان کد روی MySQL و SQLite کار می‌کند |
| `PyMySQL` | ۱.۲ | درایور MySQL خالص پایتون (بدون کامپایل، مناسب ویندوز) |
| `PyJWT` | ۲.۱۵ | توکن ورود |
| `passlib` | ۱.۷ | هش گذرواژه با PBKDF2-SHA256 |
| `cryptography` | ۵۰ | رمزنگاری توکن سرویس ابری با Fernet (AES) در پایگاه داده |
| `httpx` | ۰.۲۸ | ارتباط با سرویس ابری |
| `openpyxl` | ۳.۱ | خروجی اکسل |
| `pypdf` | ۷.۰ | متن PDF متنی بدون OCR |
| `python-multipart` | ۰.۰۳ | آپلود فایل |

**اختیاری (نصب نشده، در requirements کامنت است):**
`pytesseract` + `pillow` + `pdf2image` — اگر Tesseract روی سیستم نصب باشد،
OCR تصویر محلی هم ممکن می‌شود. بدون آن، فایل تصویری به سرویس ابری می‌رود.

### پایگاه داده — ۱۱ جدول

`User` · `Plan` · `LicenseKey` · `Subscription` · `Invoice` · `InvoiceItem` ·
`OcrJob` · `AuditLog` · `AppSetting` · `Device` · `SupportMessage`

روی WAMP همان MySQL خودش کار می‌کند (`utf8mb4_persian_ci`)، و اگر نصب نباشد
SQLite در یک فایل. هیچ migration پیچیده‌ای لازم نیست — جدول‌ها خودکار ساخته می‌شوند.

### احراز هویت و امنیت

- گذرواژه: PBKDF2-SHA256 (نه متن ساده، نه MD5)
- نشست: JWT با کلید `SECRET_KEY`
- توکن سرویس ابری: **رمزنگاری‌شده با Fernet** در ستون `AppSetting` — حتی اگر
  کسی دیتابیس را بردارد، توکن قابل استفاده نیست
- لیسانس/اشتراک: کلید با امضای HMAC
- لاگ `httpx` خاموش شده تا آدرس درگاه در هیچ لاگی نیفتد

### موتور OCR — دو مسیر

| مسیر | موتور | چه زمانی |
|---|---|---|
| `cloud` | سرویس ابری از طریق درگاه | پیش‌فرض؛ کیفیت بالا برای دست‌نویس و فاکتور حرارتی |
| `local` | `pypdf` (PDF متنی) + Tesseract (تصویر) | آفلاین، بدون مصرف اعتبار |

خروجی هر دو مسیر با یک پارسر مشترک (`services/parser.py`، ۳۸۴ خط) به فیلدهای
فاکتور تبدیل می‌شود: شماره، تاریخ، فروشنده، خریدار، اقلام، جمع، مالیات.
پارسر **قاعده‌محور با regex فارسی** است، نه مدل هوش مصنوعی — یعنی قابل پیش‌بینی
و قابل اصلاح.

## ۴. رابط کاربری

- **HTML + CSS + JavaScript خالص**، بدون فریم‌ورک، بدون مرحلهٔ build
- فونت **وزیرمتن** به‌صورت `.woff2` داخل مخزن (۲۷۲ کیلوبایت) — نه Google Fonts
- CSS دستی (۴۸ کیلوبایت) با متغیر، تم تاریک/روشن، RTL کامل
- JS به ۷ فایل تقسیم شده: `api.js` (ارتباط)، `ui.js` (کامپوننت)، `views.js` (صفحات)،
  `admin.js` (پنل مدیریت)، `compat.js` (سازگاری با مرورگرهای قدیمی)
- Service Worker برای کش آفلاین (استراتژی: شبکه اول)
- PWA: قابل نصب روی موبایل (`manifest.webmanifest`)

**چرا بدون فریم‌ورک؟** چون روی ویندوز ۷ و مرورگر قدیمی هم باید باز شود، و
چون هیچ CDN یا اینترنتی لازم نیست — همه‌چیز از همان هاست می‌آید.

## ۶. جریان کامل یک فاکتور (از کلیک تا متن)

```
۱. کاربر عکس را انتخاب می‌کند
       ↓
۲. آپلود به هاست خودتان (چند ثانیه) → فایل در fk-uploads
       ↓
۳. addfile به سرویس ابری (multipart، نام و MIME درست) → FileToken
       ↓
۴. convert با method=4 (استخراج متن) → لینک فایل Word
       ↓
۵. دانلود فایل از لینک
       ↓
۶. باز کردن ZIP و خواندن word/document.xml  ← این‌جا قبلاً متن گم می‌شد
       ↓
۷. متن در کادر صفحه (قابل ویرایش) + دکمهٔ TXT + دکمهٔ Word
       ↓
۸. deletefile — فایل از سرور ابری پاک می‌شود
```

مرحلهٔ ۶ همان چیزی است که «توکن مصرف می‌شود ولی خروجی نمی‌آید» را برطرف کرد.

## ۷. چیزهایی که عمداً استفاده **نشده**

| استفاده نشده | دلیل |
|---|---|
| Composer / npm / pip در مسیر کاربر | باید با drag & drop روی WAMP کار کند |
| React / Vue / Angular | حجم، نیاز به build، ناسازگاری با مرورگر قدیمی |
| CDN و فونت اینترنتی | اینترنت کاربر ممکن است قطع یا محدود باشد |
| ZipArchive / zlib | روی ویندوز ۷ و هاست‌های ارزان فعال نیست |
| مدل هوش مصنوعی محلی (LLM) | نیاز به GPU، حجم چند گیگابایتی |
| نام و برند سرویس ابری | قاعدهٔ محصول: فقط «سرویس ابری» |
| ذخیرهٔ توکن به متن ساده در نسخهٔ پایتون | رمزنگاری Fernet اجباری است |

## ۸. جمع‌بندی یک‌خطی

> فاکتورخوان یک برنامهٔ **PHP خالص** برای WAMP/htdocs است که عکس فاکتور را از طریق
> یک **سرویس ابری OCR** به متن تبدیل می‌کند، متن را از فایل Word بیرون می‌کشد و
> در یک کادر قابل ویرایش نشان می‌دهد — بدون هیچ کتابخانهٔ بیرونی، بدون Composer،
> و بدون لو دادن نام سرویس‌دهنده.
>
> نسخهٔ کامل (اختیاری) با **Python + FastAPI + SQLAlchemy** همین کار را چندکاربره
> با اشتراک، فاکتور، اکسل و پنل مدیریت انجام می‌دهد.
