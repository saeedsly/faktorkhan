# معماری فاکتورخوان

## ۱. نمای کلی

فاکتورخوان یک برنامه **دو‌لایه** است که هر دو لایه در یک پروسه Python اجرا می‌شوند:

```
مرورگر/دسکتاپ  ──HTTP/JSON──▶  FastAPI (API + منطق)  ──SQLAlchemy──▶  SQLite | MySQL
                                        │
                                        ├──▶  موتور لوکال (pypdf / Tesseract)
                                        └──▶  درگاه ابری (فقط سمت سرور)
```

**تصمیم‌های کلیدی:**

| تصمیم | دلیل |
|---|---|
| یک سرویس واحد به‌جای چند میکروسرویس | استقرار روی یک سرور ساده، نگه‌داری آسان، بدون صف پیام |
| رابط کاربری بدون build (HTML/CSS/JS) | نصب بدون Node.js، اجرا در پنجره دسکتاپ، کش ساده |
| پردازش پس‌زمینه با Thread | جلوگیری از قفل شدن درخواست‌های طولانی OCR، بدون وابستگی به Celery/Redis |
| دو موتور OCR پشت یک رابط | کاربر انتخاب می‌کند؛ دقت ابری + استقلال لوکال |
| SQLite برای دسکتاپ، MySQL برای سرور | نصب بدون پیش‌نیاز برای ویندوز، مقیاس‌پذیری در سرور |

## ۲. لایه‌ها

### `backend/app/config.py`

تنظیمات از متغیر محیطی یا فایل `.env` خوانده می‌شود. اگر `SECRET_KEY` یا
`ENCRYPTION_KEY` تعیین نشده باشد، در پوشه داده ساخته و پایدار می‌شود (مناسب نصب دسکتاپ).
`app_meta()` فقط داده عمومی برمی‌گرداند؛ **آدرس درگاه ابری در آن نیست**.

### `backend/app/database.py`

موتور SQLAlchemy با سازگاری SQLite (WAL، foreign_keys) و MySQL (utf8mb4، pool، pre_ping).
`init_db()` جداول را در اولین اجرا می‌سازد.

### `backend/app/models.py`

| جدول | نقش |
|---|---|
| `users` | کاربر، نقش، وضعیت، قفل ورود، تماس، تم |
| `plans` | طرح اشتراک: قیمت، مدت، سهمیه، دستگاه، ویژگی‌ها |
| `license_keys` | کد یک‌بارمصرف با وضعیت `unused/used/revoked` |
| `subscriptions` | اشتراک: تاریخ پایان، پشتیبانی، سهمیه و مصرف، دستگاه‌ها |
| `invoices` | فاکتور: طرفین، مبالغ، وضعیت، منبع، اعتماد، متن OCR، فایل |
| `invoice_items` | ردیف اقلام |
| `ocr_jobs` | کار پردازش: موتور، روش، خروجی، پیشرفت، متن، فراداده تحلیلی |
| `app_settings` | تنظیمات پویا + توکن ابری **رمزنگاری‌شده** |
| `audit_logs` | گزارش رویداد با آی‌پی و عامل کاربری |
| `devices` | دستگاه‌های فعال هر کاربر |
| `support_messages` | پیام‌های پشتیبانی و پاسخ‌ها |

### `backend/app/security.py`

- `hash_password` / `verify_password` → PBKDF2-SHA256
- `create_access_token` / `decode_token` → JWT HS256 با `jti`
- `encrypt_secret` / `decrypt_secret` → Fernet با کلید مشتق‌شده از `ENCRYPTION_KEY`
- `mask_secret` → نمایش امن `••••••••abcd`
- `generate_license_key` → قالب `FK-XXXX-XXXX-XXXX-XXXX-CC` با رقم کنترلی SHA-256

### `backend/app/deps.py`

احراز هویت، نقش‌ها، اشتراک فعال، مصرف سهمیه، محدودیت دستگاه، محدودیت نرخ در حافظه و
ثبت رویداد.

## ۳. جریان خوانش فاکتور

```
۱. کاربر فایل را انتخاب می‌کند (یا لینک/متن)
۲. POST /api/ocr/upload  →  فایل در storage/uploads/<user_id>/ ذخیره می‌شود
۳. رکورد ocr_jobs با وضعیت queued ساخته می‌شود
۴. thread پس‌زمینه jobs.run(job_id) اجرا می‌شود
      ├─ ابری:  addfile → (convert) → checkconvert/download → deletefile
      └─ لوکال: pypdf/Tesseract → متن
۵. parser.parse_invoice(text) → فیلدها، اقلام، امتیاز اعتماد، هشدارها
۶. خروجی در job.meta["parsed"] ذخیره می‌شود
۷. رابط کاربری هر ۱٫۴ ثانیه وضعیت را می‌پرسد و پیشرفت را نشان می‌دهد
۸. انسان فیلدها را بازبینی می‌کند
۹. POST /api/ocr/jobs/{id}/to-invoice → ثبت فاکتور + مصرف سهمیه
```

**چرا thread؟** پردازش ابری می‌تواند تا چند دقیقه طول بکشد. هر کار در thread جداگانه با
نشست پایگاه داده مستقل (`session_scope`) اجرا می‌شود تا درخواست HTTP آزاد بماند.

## ۴. موتور استخراج متن (`services/parser.py`)

1. **نرمال‌سازی:** ارقام فارسی/عربی → لاتین، `ي`→`ی`، `ك`→`ک`، حذف نیم‌فاصله.
2. **بازسازی سطر:** اگر PDF متن را بدون شکست خط داده باشد، `auto_break_lines()` سطرها را
   بر اساس برچسب‌های آشنا و مرزهای واژه بازسازی می‌کند.
3. **حفظ ستون‌ها:** فاصله‌های دوگانه به tab تبدیل می‌شود تا ردیف‌های جدول قابل تفکیک باشند.
4. **استخراج فیلدها:** الگوهای فارسی و انگلیسی برای شماره، تاریخ، طرفین، شناسه ملی.
5. **مبالغ:** تفکیک «جمع اقلام»، «جمع کل»، «تخفیف»، «مالیات»، «قابل پرداخت».
6. **اقلام:** تشخیص ردیف با حداقل دو عدد و متن؛ محاسبه تعداد از تقسیم مبلغ بر قیمت واحد.
7. **امتیاز اعتماد:** جمع وزن فیلدهای یافته (۰ تا ۱۰۰) + هشدارهای ناسازگاری.

این ماژول کاملاً مستقل و قابل تست است:

```bash
python -c "from app.services.parser import parse_invoice; print(parse_invoice(open('t.txt').read()))"
```

## ۵. امنیت توکن ابری (مدل تهدید)

| تهدید | دفاع |
|---|---|
| مشاهده توکن در مرورگر | توکن هرگز در پاسخ API نیست؛ فقط `token_set` و اثر انگشت مخفی |
| خواندن توکن از پایگاه داده | رمزنگاری Fernet با کلید محیطی |
| لو رفتن توکن در لاگ/خطا | `_scrub()` همه رخدادهای توکن را حذف می‌کند |
| بازپخش توکن کاربر | JWT با انقضا و شناسه یکتا |
| سوءاستفاده از API ابری | همه تماس‌ها از سرور و با توکن سرور؛ کاربر به درگاه دسترسی ندارد |
| باقی ماندن فایل روی سرور ابری | حذف خودکار پس از پردازش (`delete_after`) |
| حملات نرخ | محدودیت درخواست روی ورود/ثبت‌نام/بارگذاری |
| آپلود مخرب | لیست سفید پسوند + محدودیت حجم + پوشه اختصاصی هر کاربر |

## ۶. چند‌مستأجری و نقش‌ها

- هر فاکتور، کار و فایل به `user_id` تعلق دارد؛ همه کوئری‌ها با `user_id` فیلتر می‌شوند.
- `owner` = مالک سامانه (حذف کاربر، پشتیبان‌گیری، تعیین مالک).
- `admin` = مدیر عملیاتی (کاربران، طرح‌ها، کدها، توکن، تنظیمات).
- `user` = کاربر عادی (فاکتورها، خوانش، اشتراک خود).

---

## ۷. مقیاس‌پذیری

- برنامه **بدون حالت** است؛ چند نمونه پشت Nginx قابل اجراست (JWT، بدون session سروری).
- پردازش پس‌زمینه در حافظه است؛ برای بار سنگین می‌توان `jobs.start` را به صف خارجی متصل کرد
  (نقطه اتصال تک و مشخص است).
- پایگاه داده: ایندکس روی `user_id+status`، `issue_date`، `created_at`.
- فایل‌ها در دیسک؛ برای مقیاس بیشتر می‌توان `storage` را روی NFS/S3 mount کرد.
