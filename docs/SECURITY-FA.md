# امنیت فاکتورخوان روی اینترنت — چک‌لیست عملی

این سند برای وقتی است که برنامه از `127.0.0.1` بیرون می‌رود و روی دامنهٔ عمومی
سرو می‌شود. هر ردیف را انجام دهید و تیک بزنید.

---

## ۱. آنچه همین حالا در برنامه تعبیه شده است

| محافظت | جزئیات |
|---|---|
| هدرهای امنیتی | `Content-Security-Policy` سخت‌گیر، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy: no-referrer` |
| HSTS | وقتی `FORCE_HTTPS=1` باشد ارسال می‌شود |
| بررسی هدر Host | `TrustedHostMiddleware` با فهرست `ALLOWED_HOSTS` |
| CORS | در `production` مقدار `*` نادیده گرفته می‌شود (همان‌مبدأ) |
| محدودیت تلاش ورود | ۷ تلاش ناموفق → قفل ۱۵ دقیقه‌ای (`MAX_LOGIN_ATTEMPTS`, `LOCK_MINUTES`) |
| محدودیت حجم آپلود | `MAX_UPLOAD_MB` (پیش‌فرض ۲۵ مگابایت) + بررسی `Content-Length` |
| مستندات API | در `production` بسته است (`ENABLE_API_DOCS=0`) |
| توکن سرویس ابری | رمزنگاری‌شده در پایگاه؛ هیچ‌گاه در پاسخ API یا لاگ ظاهر نمی‌شود |
| لاگ درخواست‌های بیرونی | `httpx`/`httpcore` روی WARNING تنظیم شده تا آدرس درگاه لو نرود |
| گذرواژه | هش SHA-256 با نمک (passlib) — گذرواژهٔ خام ذخیره نمی‌شود |
| توکن نشست | JWT با انقضای `TOKEN_TTL_HOURS` (پیش‌فرض ۱۶۸ ساعت) |
| مسیر فایل‌ها | محافظت در برابر Path Traversal در سرو فایل‌های استاتیک |

## ۲. کارهای اجباری قبل از انتشار

### الف) تنظیمات `.env`

| کلید | مقدار لازم | چرا |
|---|---|---|
| `APP_ENV` | `production` | حالت سخت‌گیرانه |
| `SECRET_KEY` | ۴۸ بایت تصادفی | بدون آن توکن‌ها قابل جعل می‌شوند |
| `ENCRYPTION_KEY` | ۴۸ بایت تصادفی | رمزنگاری توکن سرویس ابری |
| `DATABASE_URL` | MySQL با کاربر اختصاصی | نه `root` |
| `ALLOWED_HOSTS` | دامنه‌های واقعی | جلوی Host header injection |
| `FORCE_HTTPS` | `1` | HSTS و کوکی امن |
| `PROXY_HEADERS` | `1` | IP واقعی کاربر برای محدودسازی تلاش ورود |
| `ENABLE_API_DOCS` | `0` | مستندات عمومی لازم نیست |
| `ALLOW_REGISTRATION` | `false` | فقط با کد لایسنس وارد شوند |
| `HOST` | `127.0.0.1` | پورت ۸۰۰۰ از بیرون دیده نشود |
| `MAX_UPLOAD_MB` | ۱۰ تا ۲۵ | جلوگیری از پر شدن دیسک |

`SETUP-MYSQL-WINDOWS.bat` این‌ها را خودکار می‌سازد و مقدار می‌دهد.

### ب) حساب مالک

- [ ] بعد از اولین ورود، گذرواژه را در **تنظیمات → امنیت** عوض کنید
- [ ] فایل `storage\OWNER-CREDENTIALS.txt` را پاک کنید
- [ ] ایمیل مالک را به ایمیل واقعی خودتان تغییر دهید (برای بازیابی)

### ج) شبکه و فایروال

```
فقط این پورت‌ها از بیرون باز باشند:
   80  (HTTP → ریدایرکت به HTTPS)
  443  (HTTPS)
بسته باشند:
  8000 (برنامهٔ پایتون — فقط داخلی)
  3306 (MySQL — هرگز روی اینترنت نباشد)
  8080 (phpMyAdmin — روی اینترنت نباشد)
```

در ویندوز:

```bat
netsh advfirewall firewall add rule name="HTTP"  dir=in action=allow protocol=TCP localport=80
netsh advfirewall firewall add rule name="HTTPS" dir=in action=allow protocol=TCP localport=443
netsh advfirewall firewall set rule name="FactorKhan" new enable=no
```

> ⚠️ اگر MySQL باید از سیستم دیگری در شبکه در دسترس باشد، آن را با
> `bind-address = 127.0.0.1` در `my.ini` محدود و فقط از طریق IP داخلی اجازه دهید.
> `bind-address = 0.0.0.0` روی اینترنت یعنی فاجعه.

### د) پایگاه داده

- [ ] کاربر `faktorkhan` فقط به پایگاه `faktorkhan` دسترسی دارد (نه `root`)
- [ ] گذرواژهٔ پایگاه حداقل ۲۰ کاراکتر تصادفی
- [ ] phpMyAdmin روی اینترنت در دسترس نیست (یا با IP محدود شود)
- [ ] پشتیبان روزانه با `mysqldump` (دستور در `DEPLOY-WINDOWS-WAMP.md`)
- [ ] پشتیبان‌ها جایی خارج از سرور نگه‌داری شوند

### هـ) HTTPS

- [ ] گواهی معتبر (Let's Encrypt / win-acme) نصب شده
- [ ] `http://` به `https://` ریدایرکت می‌شود
- [ ] فقط TLS 1.2 و 1.3 فعال است
- [ ] تمدید خودکار تست شده (`https://www.ssllabs.com/ssltest/` نمرهٔ A بدهد)

## ۳. سخت‌گیری بیشتر (اختیاری ولی توصیه‌شده)

### محدود کردن پنل مدیریت به IP خودتان (Apache)

```apache
<LocationMatch "^/api/admin/">
    Require ip 203.0.113.10
</LocationMatch>
```

### محدودیت نرخ درخواست (Apache)

```apache
# در httpd.conf
LoadModule ratelimit_module modules/mod_ratelimit.so

<IfModule mod_ratelimit.c>
    <Location /api/auth/login>
        SetOutputFilter RATE_LIMIT
        SetEnv rate-limit 30
    </Location>
</IfModule>
```

### Cloudflare (لایهٔ رایگان)

- DNS را به Cloudflare منتقل کنید (پروکسی نارنجی)
- `ALLOWED_HOSTS` را با دامنه تنظیم کنید (نه IP)
- در Cloudflare: **SSL/TLS → Full (strict)** تا رمزنگاری انتها‌به‌انتها باشد
- در Apache برای دیدن IP واقعی، `mod_remoteip` را فعال کنید

### سرویس ویندوز با کاربر محدود

برنامه را به‌عنوان سرویس (`nssm`) با یک کاربر ویندوزی **بدون دسترسی Administrator**
اجرا کنید و فقط به پوشهٔ `C:\faktorkhan` دسترسی بدهید.

### به‌روزرسانی

```bat
python -m pip install -r backend\requirements.txt --upgrade
```

سه‌ماهی یک‌بار کتابخانه‌ها و ویندوز را به‌روز کنید (پس از گرفتن پشتیبان).

## ۴. پایش و واکنش

| چه چیزی را ببینیم | کجا |
|---|---|
| سلامت برنامه | `GET /api/system/health` |
| لاگ دسترسی | `C:\wamp64\logs\faktorkhan-ssl-access.log` |
| لاگ خطا | `C:\wamp64\logs\faktorkhan-ssl-error.log` |
| تلاش‌های ورود ناموفق | پنل مدیریت → گزارش‌ها |
| مصرف اعتبار ابری | پنل مدیریت → سرویس ابری → تست اتصال و اعتبار |

**اگر نفوذ مشکوک بود:**
1. سایت را پایین بیاورید (`Stop-Service FactorKhan` یا Apache را Stop کنید)
2. `SECRET_KEY` را عوض کنید (همهٔ نشست‌ها باطل می‌شوند) و برنامه را ری‌استارت کنید
3. گذرواژهٔ مالک و کاربران را عوض کنید
4. توکن سرویس ابری را از پنل مدیریت **حذف** و توکن جدید ثبت کنید
5. از `mysqldump` و `storage` پشتیبان بگیرید، بعد لاگ‌ها را بررسی کنید
6. اگر داده لو رفته، مشتریان را مطلع کنید

## ۵. کارهایی که عمداً انجام **نشده** (برای شفافیت)

| مورد | وضعیت | دلیل |
|---|---|---|
| ورود دومرحله‌ای (2FA) | ندارد | برای نسخهٔ بعدی برنامه‌ریزی شده؛ فعلاً با گذرواژهٔ قوی + محدودیت IP جبران کنید |
| نشست مبتنی بر کوکی HttpOnly | ندارد | از JWT در حافظهٔ مرورگر استفاده می‌شود؛ با CSP سخت‌گیرانه ریسک XSS پوشش داده شده |
| محدودیت نرخ در سطح برنامه | محدود به ورود | برای بقیهٔ مسیرها از `mod_ratelimit` یا Cloudflare استفاده کنید |
| رمزنگاری فایل‌های بارگذاری‌شده روی دیسک | ندارد | اگر داده حساس است، از BitLocker یا پوشهٔ رمزنگاری‌شده استفاده کنید |
