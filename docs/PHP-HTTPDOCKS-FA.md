# فاکتورخوان — نسخهٔ PHP برای WAMP / XAMPP (htdocs)

ساخته‌شده برای **ویندوز ۷ / WAMP / XAMPP**: بدون Composer، بدون build،
بدون پایگاه داده. فقط فایل‌ها را در `htdocs` بریزید و باز کنید.

> **همان برنامهٔ پایتون، با PHP.** یک رابط، دو بک‌اند: همان ظاهر و همان
> نُه بخش (داشبورد، خوانش، فاکتورها، گزارش‌ها، اشتراک، قابلیت‌ها،
> پشتیبانی، تنظیمات، مدیریت) و همان ۱۲۰ قابلیت.
>
> چیزهایی که عمداً نیست: پایگاه دادهٔ MySQL (همه‌چیز روی فایل JSON است،
> پس پشتیبان = کپی یک پوشه) و سرویس‌ورکر PWA (برای اینکه باگ «کش قدیمی
> بعد از آپدیت» پیش نیاید).

---

## گام ۱: فایل‌ها را در htdocs بگذارید

```
C:\wamp64\www\faktorkhan\
    index.php              پوستهٔ برنامه (SPA)
    api.php                سرویس JSON — ۶۳ اکشن
    api_helpers.php        منطق مسیرها (فاکتور، کار، آمار، مدیریت)
    store.php              کاربران، طرح‌ها، اشتراک‌ها، کدها، تنظیمات
    data.php               متن برند، ۱۲۰ قابلیت، پرسش‌های متداول
    lib.php                هستهٔ مشترک (نشست، امنیت، کارها، پیکربندی)
    library.php            بایگانی فاکتورها (ثبت، جست‌وجو، آمار، CSV)
    engine.php             موتور پاک‌سازی و فهم متن فاکتور
    legacy.php             رابط سادهٔ قدیمی (فقط اگر web/ نبود)
    .htaccess              محافظت فایل‌ها و پوشه‌ها
    config.sample.php      (اختیاری — برای الگو)
    web\
        index.html         رابط
        app.js             اسکریپت رابط (۱۹۶ KB)
        app.css            استایل رابط (۴۸ KB)
        assets\fonts\      وزیرمتن (۵ وزن) + فاوآیکون
```

⚠️ **پوشهٔ `web/` را جابه‌جا یا پاک نکنید.** اگر نباشد، برنامه خودش به
`legacy.php` برمی‌گردد؛ کار می‌کند ولی پنل کامل نیست.

پوشه‌های `fk-data`، `fk-jobs`، `fk-uploads`، `fk-sessions`، `fk-invoices`
هنگام اجرا خودکار ساخته می‌شوند. همه در `.gitignore` هستند و نباید در
بستهٔ نصبی باشند.

از پوشهٔ `deploy/php` در بستهٔ نصبی بردارید. اگر WAMP شما ۳۲ بیتی است مسیر
`C:\wamp\www\faktorkhan` است.

## گام ۲: curl را فعال کنید

آیکن WAMP (سبز) → **PHP** → **php.ini** → خط زیر را از کامنت خارج کنید:

```ini
extension=curl
```

سپس **Restart All Services**. (WAMP معمولاً curl را از قبل فعال دارد؛ صفحه خود
وضعیت را نشان می‌دهد.)

## گام ۳: باز کنید

```
http://localhost/faktorkhan/
```

صفحهٔ ورود می‌آید. سه مرحله:

| مرحله | چه می‌کنید |
|---|---|
| ۱ | **ثبت‌نام** می‌کنید (نام، ایمیل، گذرواژه) — اولین حساب، مالک سامانه می‌شود |
| ۲ | در **تنظیمات**، **توکن** را می‌چسبانید و «ذخیره» می‌زنید |
| ۳ | دکمهٔ **تست اعتبار** — باید بگوید «اعتبار OCR: ... صفحه» |

بعد از این، **فایل را انتخاب کنید** → **ارسال و خوانش** → متن فاکتور نمایش داده می‌شود.

> کاربران بعدی از همان صفحهٔ ورود **ثبت‌نام** می‌کنند و حساب جداگانه
> می‌گیرند (نقش `user`). مالک و مدیر می‌توانند از پنل مدیریت حساب بسازند،
> غیرفعال کنند یا طرح بدهند.

## چه چیزی امن است؟

| مورد | چطور |
|---|---|
| توکن | در `fk-config.json` با مجوز 0600، مسدودشده با `.htaccess`؛ در هیچ صفحه‌ای چاپ نمی‌شود |
| آدرس درگاه | مبهم‌سازی‌شده در کد (XOR + Base64)؛ در صفحه و لاگ نمی‌آید |
| گذرواژه | `password_hash()` با الگوریتم پیش‌فرض PHP (bcrypt)؛ هش هرگز به رابط نمی‌رود |
| نشست | کوکی `HttpOnly` + `SameSite=Lax` (+ `Secure` روی HTTPS)، نام اختصاصی `fksid` |
| تلاش ورود | ۸ تلاش در ۱۵ دقیقه، بعد قفل موقت؛ شمارنده بر پایهٔ IP |
| نقش‌ها | `owner`/`admin`/`user`؛ هر مسیر مدیریت پیش از اجرا نقش را بررسی می‌کند |
| دادهٔ کاربران | هر کوئری فاکتور با `user_id` فیلتر می‌شود؛ خواندن فاکتور دیگری ۴۰۴ |
| توکن ابری | فقط «ماسک» در پاسخ API (`••••••12345`)؛ کامل هرگز برنمی‌گردد |
| لینک دانلود خروجی | فقط `http/https`؛ لینک از پاسخ JSON خوانده می‌شود نه از ورودی کاربر (ضد SSRF) |
| آپلودها | در `fk-uploads` با `.htaccess` و `server.php` مسدود؛ نام تصادفی |
| کارها و نشست‌ها | `fk-jobs/` و `fk-sessions/` هر دو مسدود؛ JSON کارها فقط از راه API خوانده می‌شود |
| پیام خطا | توکن در پیام‌ها با «مخفی» جانشین می‌شود |

## اگر صفحه باز نمی‌شود و «همش می‌چرخد»

این تقریباً همیشه یکی از این سه چیز است:

### ۱) `https://` به‌جای `http://` ✋
WAMP به‌طور پیش‌فرض **SSL ندارد**. اگر آدرس را با `https://localhost/...` باز کنید،
مرورگر بی‌پایان منتظر می‌ماند (همان چرخیدن). آدرس درست:

```
http://localhost/faktorkhan/
```

اگر مرورگر خودش `https` را اضافه می‌کند: در نوار آدرس `chrome://settings/security` →
«Always use secure connections» را خاموش کنید، یا از حالت ناشناس استفاده کنید.

### ۲) نام پوشه اشتباه
آدرس باید **دقیقاً** با نام پوشه در `www` بخواند. اگر پوشه `faktorkhan` است:

```
C:\wamp64\www\faktorkhan\index.php      ✅
http://localhost/faktorkhan/                ✅
```

اگر پوشه را `facktorkhan` (با c اضافه) ساخته‌اید، آدرس هم باید همان باشد. ساده‌ترین کار:
پوشه را به `faktorkhan` تغییر نام دهید.

### ۳) Apache یا MySQL خاموش است
آیکن WAMP باید **سبز** باشد. اگر نارنجی/قرمز است، Apache شروع نشده (معمولاً چون
پورت ۸۰ اشغال است — IIS یا Skype). آیکن → Apache → **Test port 80**.

## راه جایگزین: بدون Apache (توصیه می‌شود اگر WAMP اذیت می‌کند)

فایل `START-PHP-SERVER.bat` را دوبار کلیک کنید. خودش `php.exe` را در WAMP پیدا می‌کند،
یک پورت آزاد انتخاب می‌کند، سرور داخلی PHP را بالا می‌آورد و مرورگر را باز می‌کند:

```
http://127.0.0.1:8080/
```

مزیت: نیازی به Apache، `.htaccess` یا تنظیم سرویس نیست. فایل‌های حساس هم با
`server.php` مسدود می‌شوند.

اگر می‌خواهید دستی اجرا کنید (در پوشهٔ برنامه):

```bat
"C:\wamp64\bin\php\php8.0.30\php.exe" -S 127.0.0.1:8080 -t . server.php
```

> پورت را از پوشهٔ `C:\wamp64\bin\php` بردارید.

## چرا صفحه دیگر قفل نمی‌شود و اعتبار هدر نمی‌رود

تبدیل فاکتور روی سرویس ابری ممکن است از چند ثانیه تا چند دقیقه طول بکشد.
اگر همهٔ این مدت داخل یک درخواست HTTP بماند، دو اتفاق بد می‌افتد:

1. سرور داخلی PHP **تک‌رشته‌ای** است؛ تا پایان کار، کل سایت (حتی صفحهٔ ورود) قفل می‌شود.
2. مرورگر یا پروکسی هاست تایم‌اوت می‌کند و **صفحهٔ سفید** می‌شود؛ کاربر دوباره «ارسال» را
   می‌زند و هر تلاش یک فایل جدید روی سرویس ابری ثبت می‌کند ⇒ **اعتبار/توکن هدر می‌رود**.

نسخهٔ فعلی هر فایل را به یک «کار» (job) تبدیل می‌کند و کار را چهار مرحله‌ای پیش می‌برد:

| مرحله | کاری که انجام می‌شود | زمان |
|---|---|---|
| `addfile` | ارسال فایل به سرویس ابری و گرفتن شناسهٔ فایل | چند ثانیه |
| `convert` | درخواست شروع تبدیل با روش مناسب (عکس ⇒ روش ۴) | چند ثانیه |
| `wait` | پرسیدن درصد پیشرفت | کمتر از ۲۰ ثانیه |
| `download` | دریافت فایل خروجی، در صورت نیاز | متغیر |

**قاعدهٔ زمان‌بندی (برای سرعت):**

* دو مرحلهٔ قطعاً کوتاه (`addfile` و `convert`) در **همان یک درخواست** انجام می‌شوند؛
  هر کدام ۱ تا ۵ ثانیه‌اند و مجموعشان صفحه را قفل نمی‌کند، ولی حذف رفت‌وبرگشت
  مرورگر ۲ تا ۳ ثانیه صرفه‌جویی می‌کند.
* `checkconvert` (که ممکن است دقایق طول بکشد) **هرگز تکرار نمی‌شود**؛ هر درخواست
  فقط یک بار آن را می‌پرسد تا پاسخ کوتاه بماند.
* بین مراحل کوتاه، مرورگر **بدون تأخیر** (۱۲۰ میلی‌ثانیه) درخواست بعدی را می‌فرستد.

نتیجه: سرعت کل تقریباً برابر روش قبلی است (فقط ۰.۱ تا ۱ ثانیه سرباره)، در حالی که
صفحه هیچ‌وقت قفل نمی‌شود.

### چرا «۹۷٪» گیر نمی‌کند

درصد پیشرفت فقط وقتی نمایش داده می‌شود که **سرویس ابری خودش درصد بدهد**. اگر سرویس
درصد ندهد، برنامه هیچ عدد ساختگی نشان نمی‌دهد؛ به‌جای آن:

* نوار پیشرفت حالت **متحرک** می‌گیرد (نشانهٔ «در جریان است»)،
* **زمان‌سنج واقعی** («۴۲ ثانیه»، «۲ دقیقه و ۵ ثانیه») نمایش داده می‌شود،
* بعد از ۷ دقیقه پیام صریح می‌آید: «سرویس ابری بیش از ۷ دقیقه پاسخ آماده نداده…»
  و دکمهٔ **لغو پردازش** در دسترس است.

### سریع‌ترین تنظیم

قالب خروجی پیش‌فرض **«متن ساده»** است (سریع‌ترین). گزینهٔ «متن + مختصات (JSON)»
موقعیت هر کلمه را هم می‌خواهد و **چند برابر کندتر** است؛ برای فاکتور معمولی لازم نیست.

**قاعدهٔ اصلی: هیچ درخواستی منتظر پایان OCR نمی‌ماند.** مرورگر با فاصلهٔ تطبیقی
(۱.۵ تا ۵ ثانیه) وضعیت را می‌پرسد و نوار پیشرفت را جلو می‌برد. نتیجه:

* صفحه هیچ‌وقت قفل نمی‌شود و «صفحهٔ سفید» نداریم.
* اگر اینترنت قطع شود، کار از بین نمی‌رود؛ همان فایل ادامه پیدا می‌کند (بدون آپلود دوباره).
* اگر مرورگر را ببندید، کار در پوشهٔ `fk-jobs` می‌ماند و بعد از باز کردن صفحه، از بخش
  **«کارهای اخیر»** قابل دیدن است.
* دکمهٔ **«لغو پردازش»** علاوه بر توقف کار، فایل را از سرویس ابری هم حذف می‌کند.
* پس از پایان، فایل ورودی از سرور پاک و (در صورت فعال بودن گزینهٔ پیش‌فرض) فایل روی سرویس
  ابری هم حذف می‌شود.

پوشه‌های `fk-jobs`، `fk-uploads` و `fk-sessions` خودکار ساخته می‌شوند، از طریق مرورگر
قابل دسترسی نیستند (`server.php` و `.htaccess` هر دو می‌بندند) و کارهای قدیمی‌تر از ۲ روز
خودکار پاک می‌شوند.

## یافته‌های آزمون واقعی سرویس ابری

با اجرای `diag.php` روی هاست، رفتار سرویس مشخص شد. این جدول نتیجهٔ آزمون واقعی است:

| آزمون | نام فایل | MIME | نتیجه |
|---|---|---|---|
| ۱ | `invoice-sample.png` | `image/png` | ✅ توکن فایل دریافت شد |
| ۲ | `phpdiag2793.tmp` | `application/octet-stream` | ❌ `500 Error` |
| ۳ | `invoice-sample.png` | (بدون MIME) | ✅ توکن فایل دریافت شد |
| ۴ | کلید `FileHandle` با حرف بزرگ | — | ❌ `UnkwonURL` |

**درس‌های عملی که در برنامه اعمال شد:**

1. **نام فایل مهم است، نه فقط محتوا.** سرویس از پسوند نام فایل نوع فایل را تشخیص می‌دهد.
   اگر نام فایل موقت (`phpXXXX.tmp`) یا بی‌پسوند برود، خطای ۵۰۰ می‌دهد.
   → برنامه نام اصلی را نگه می‌دارد و کاراکترهای خطرناک را با `-` جایگزین می‌کند
   (`فاکتور خرید ۱۴۰۴.PNG` → `فاکتور-خرید-۱۴۰۴.png`).
2. **`application/octet-stream` را نفرستید.** فرستادن MIME عمومی باعث خطای ۵۰۰ می‌شود،
   ولی **حذف کامل MIME** کار می‌کند (سرویس خودش حدس می‌زند).
   → برنامه اگر MIME مطمئن نداشت، آن را اصلاً نمی‌فرستد.
3. **کلید باید `filehandle` باشد، نه `FileHandle`.** حرف بزرگ باعث `UnkwonURL` می‌شود.
4. **`ConvertMethods` برای عکس فقط `"4"` است** (استخراج متن). یعنی روش‌های ۱ تا ۳
   (Word) برای عکس و فاکتور دست‌نویس اصلاً در دسترس نیستند؛ برنامه خودکار روش ۴ را می‌فرستد.

> اگر باز هم خطا گرفتید، `diag.php` را یک بار دیگر اجرا کنید؛ بالای صفحه یک
> **خلاصهٔ خودکار** می‌آید که می‌گوید کدام مرحله درست کار می‌کند و کدام نه.

## چرا خروجی نمی‌آید (و توکن مصرف می‌شود)

اگر «تبدیل انجام شد» ولی متنی برای شما نمی‌آید، این سه علت را بررسی کنید. هر سه
در نسخهٔ فعلی برطرف شده‌اند:

### ۱) کلید پاسخ سرویس فاصله دارد

سرویس ابری لینک فایل را با کلیدی برمی‌گرداند که **فاصله در دو طرفش** دارد:

```json
{ "Status": "Done", " FileToDownload ": "https://…/OutputFile.Docx" }
```

اگر کد فقط `FileToDownload` را دقیق بخواند، لینک را پیدا نمی‌کند و خروجی خالی می‌ماند —
در حالی که توکن مصرف شده است. برنامهٔ فعلی کلید را با تحمل فاصله/زیرخط/حروف بزرگ می‌خواند.

### ۲) منتظر ماندن روی `checkconvert` برای عکس

طبق قرارداد سرویس:

| نوع فایل | مسیر درست |
|---|---|
| عکس و PDF | `addfile` → `convert` → **لینک در همان پاسخ `convert`** → دانلود |
| صوتی | `addfile` → `convert` → `checkconvert` (تکرار) → متن |

برنامه قبلاً برای همهٔ فایل‌ها `checkconvert` می‌زد. برای عکس بی‌فایده بود و فقط
وقت و اعتبار تلف می‌کرد. حالا اگر `convert` لینک بدهد، بی‌درنگ دانلود می‌شود.

### ۳) متن در وضعیت `Converting` نادیده گرفته می‌شد

سرویس متن را تدریجی می‌فرستد و ممکن است با `Status: "Converting"` هم `Output` داشته باشد.
برنامه قبلاً متن را فقط با `Status: "Done"` قبول می‌کرد. حالا هر متنی که بیاید پذیرفته می‌شود.

همچنین `Data Not Found Yet` که در مستندات جزو «خطاها» فهرست شده، در عمل یعنی
«هنوز آماده نیست»؛ قبلاً کار را می‌کشت، حالا ادامه می‌دهد.

### آزمون مسیر کامل با `diag.php`

نسخهٔ جدید `diag.php` دیگر فقط `addfile` را تست نمی‌کند؛ **کل مسیر واقعی** را می‌رود:

1. `checkcredit` — اعتبار
2. `addfile` — چهار روش ارسال
3. **`convert`** — تبدیل واقعی و گرفتن لینک
4. **دانلود فایل خروجی** — همان لینکی که برنامه استفاده می‌کند

بالای صفحه یک **خلاصه** می‌آید که صریح می‌گوید کدام مرحله موفق است و کدام نه.
اگر مرحلهٔ ۶ لینک داد ولی مرحلهٔ ۷ خالی بود، یعنی لینک دانلود برای سرور شما
قابل دسترسی نیست (فایروال هاست).

## متن در باکس می‌آید (نه فایل Word)

تا نسخهٔ قبل، برنامه فایل Word را ذخیره می‌کرد و متن را در صفحه نشان نمی‌داد؛
کاربر مجبور بود فایل را از `fk-uploads` بردارد — و همان فایل هم گاهی در Word
باز نمی‌شد («فایل خراب است»). حالا:

| چه می‌شود | جزئیات |
|---|---|
| **متن مستقیم در باکس** | برنامه فایل Word سرویس را باز می‌کند و متن را از `word/document.xml` بیرون می‌کشد و در یک کادر قابل ویرایش نشان می‌دهد |
| **کپی و ویرایش** | دکمهٔ «کپی متن» و امکان ویرایش در همان کادر؛ متن نهایی با «دانلود متن (TXT)» گرفته می‌شود |
| **Word سالم** | اگر بستهٔ سرویس معتبر نباشد، برنامه از همان متن یک `.docx` استاندارد می‌سازد تا در Word باز شود |
| **بدون ZipArchive** | خواندن و ساخت ZIP و باز کردن deflate داخل خود برنامه پیاده شده؛ روی ویندوز ۷ که zlib/ZipArchive ندارد هم کار می‌کند |
| **خروجی خالی** | اگر سرویس واقعاً متنی پیدا نکند، پیام صریح «عکس را واضح‌تر بگیرید» می‌آید و هیچ فایل خرابی ذخیره نمی‌شود |

نکتهٔ مهم: متن از **همان فایلی** خوانده می‌شود که سرویس فرستاده؛ هیچ درخواست
اضافه‌ای به سرویس ابری زده نمی‌شود، پس سرعت و مصرف توکن تغییر نمی‌کند.

### جدول و ستون‌ها

سرویس جدول فاکتور را در فایل Word به‌صورت `w:tc` می‌فرستد. برنامه ستون‌ها را با
**تب** و سطرها را با **خط جدید** جدا می‌کند؛ بنابراین می‌توانید متن را مستقیم در
اکسل بچسبانید و ستون‌ها خودکار تقسیم می‌شوند.

### چرا جدول اقلام خالی می‌ماند (رفع شد)

اگر متن فاکتور می‌آمد ولی جدول اقلام خالی بود، علتش **نوع جداکننده** بود:

```
کاغذ A4 — ۱۰ بسته — ۲۵۰,۰۰۰
```

فاکتور چاپی فارسی ستون‌ها را با **خط تیره** جدا می‌کند، نه با فاصله یا تب.
موتور قبلاً خط تیره را نمی‌شناخت، پس کل سطر را یک سلول می‌دید و هیچ عددی
پیدا نمی‌کرد. همچنین «۱۰ بسته» را عدد نمی‌دانست، پس تعداد را ۱ می‌گذاشت.

حالا هر سه شکل جداکننده کار می‌کند:

| جداکننده | نمونه |
|---|---|
| خط تیرهٔ فارسی (—) یا ساده (-) | `کاغذ A4 — ۱۰ بسته — ۲۵۰,۰۰۰` |
| تب (فاکتور حرارتی) | `کاغذ A4⇥۱۰ بسته⇥۲۵۰,۰۰۰` |
| ممیز عمودی (\|) | `کابل شبکه \| ۳ عدد \| ۱۲۰,۰۰۰` |

و ستون تعداد می‌تواند واحد داشته باشد: «۱۰ بسته»، «۲ عدد»، «۳ کارتن».

### اصلاح خودکار ارقام

در فاکتور فارسی عدد آخر سطر معمولاً **قیمت واحد** است، نه جمع سطر. برنامه
هر دو فرض را می‌آزماید و آن را که با **جمع کل پایین فاکتور** می‌خواند
(اختلاف کمتر از ۱٪) انتخاب می‌کند:

```
کاغذ A4  × ۱۰ × ۲۵۰,۰۰۰ = ۲,۵۰۰,۰۰۰
تونر HP  × ۲  × ۴۵۰,۰۰۰ =   ۹۰۰,۰۰۰
                       جمع = ۳,۴۰۰,۰۰۰   ← برابر جمع کل فاکتور ✓
```

اگر جمع نخواند، ارقام دست‌نخورده می‌مانند و اختلاف در بخش «اشکال‌ها» با
متن روشن گزارش می‌شود — برنامه هرگز عددی را بی‌صدا عوض نمی‌کند.

### دانلود امن

دکمه‌های دانلود از مسیر `index.php?api=file&f=txt|doc&id=…` استفاده می‌کنند و
پوشهٔ `fk-uploads` مستقیماً از وب قابل دسترسی نیست. دکمهٔ «حذف فایل‌ها» فایل‌های
ذخیره‌شده روی هاست را پاک می‌کند، ولی متن در صفحه باقی می‌ماند.

## موتور دوم: خوانش با هوش مصنوعی (برای دست‌نویس)

فاکتور دست‌نویس و عکس‌های تار/کج، سخت‌ترین حالت برای هر OCR کلاسیک هستند.
مدل‌های بینایی-زبانی روی همین تصویر بهتر عمل می‌کنند. برنامه یک موتور دوم
اختیاری دارد که دقیقاً همین کار را می‌کند.

### فعال‌کردن (۳۰ ثانیه)

1. یک کلید از سرویس هوش مصنوعی بگیرید (رایگان — سطح رایگان برای شروع کافی است)
2. در کارت «🤖 موتور هوش مصنوعی» کلید را بچسبانید و **ذخیره کلید** را بزنید
3. در فرم پردازش، «موتور خوانش» را روی **موتور هوش مصنوعی** بگذارید

اگر کلید نگذارید، همه‌چیز مثل قبل با سرویس ابری کار می‌کند و این کارت فقط «خاموش» می‌ماند.

### دو حالت استفاده

| حالت | چه می‌شود |
|---|---|
| **انتخاب مستقیم** | فایل از همان اول به موتور هوش مصنوعی می‌رود؛ سرویس ابری اصلاً صدا زده نمی‌شود (اعتبار مصرف نمی‌شود) |
| **نجات خودکار** | اگر سرویس ابری خروجی خالی داد، عکس از قبل روی سرور خودتان است و بی‌درنگ به موتور دوم می‌رود — بدون آپلود دوباره، بدون اینکه کار را از اول شروع کنید |

### چرا این خوب است

- **اعتبار سرویس ابری هدر نمی‌رود**: در حالت نجات، عکس دوباره ارسال نمی‌شود
- **سرعت**: تصویر در همان درخواست به مدل می‌رود (ماژول `ai_read_image`)
- **جدول**: مدل دستور می‌گیرد ستون‌ها را با `Tab` جدا کند؛ در اکسل مستقیم می‌چسبد
- **امنیت**: کلید فقط در `fk-config.json` روی سرور خودتان است و در صفحه فقط
  اثر انگشت مخفی (`ABCD…WXYZ`) دیده می‌شود

### هزینه

سطح رایگان حدود **۱٬۰۰۰ تا ۱٬۵۰۰ درخواست در روز** است — برای فاکتور روزانه
بیش از کافی. اگر تمام شد، پیام صریح «سهمیهٔ رایگان تمام شده» می‌آید و
کار به سرویس ابری برمی‌گردد.

### محدودیت‌ها

- به اینترنت بین‌الملل نیاز دارد (برخلاف سرویس ابری که داخلی است)
- روی عکس بزرگ، درخواست سنگین می‌شود؛ بهتر است عکس را زیر ۴ مگابایت بفرستید
- فایل صوتی پشتیبانی نمی‌شود (فقط عکس و PDF)

## موتور فهم اقلام — از متن خام تا فاکتور جدول‌دار

این بخش کار جداگانه‌ای نمی‌خواهد: **بعد از هر خوانش، خودکار اجرا می‌شود.**
هر متنی که از هر دو موتور بیاید از این خط لوله رد می‌شود.

### چه چیزی می‌بینید

بعد از تمام‌شدن کار، زیر دکمه‌های متن یک کارت **«🧠 موتور فهم اقلام»** باز می‌شود:

```
🧠 موتور فهم اقلام             [کیفیت A] ۳ قلم · اعتماد ۸۲٪ · جمع ۷٬۶۵۰٬۰۰۰    [نمای متن]
تاریخ ۱۴۰۴/۰۸/۱۶ · شماره 1404/1234 · مالیات ۹٪

┌───┬────────────────────────┬──────┬──────┬────────────┬──────────────┐
│ # │ شرح کالا / خدمت        │ تعداد│ واحد │ قیمت واحد  │ مبلغ         │
├───┼────────────────────────┼──────┼──────┼────────────┼──────────────┤
│ ۱ │ کاغذ A4 بسته 500 برگ   │  ۱۰  │ عدد  │   ۴۵۰٬۰۰۰  │  ۴٬۵۰۰٬۰۰۰   │
│ ۲ │ تونر پرینتر HP          │   ۲  │ عدد  │ ۱٬۲۰۰٬۰۰۰  │  ۲٬۴۰۰٬۰۰۰   │
│ ۳ │ خودکار آبی              │  ۵۰  │ عدد  │    ۱۵٬۰۰۰  │    ۷۵۰٬۰۰۰   │
│   │                        │      │      │            │   ۷۰۰٬۰۰۰̶   │
└───┴────────────────────────┴──────┴──────┴────────────┴──────────────┘
                                                    جمع اقلام  ۷٬۶۵۰٬۰۰۰
                                                    مالیات       ۷۶۵٬۰۰۰
                                                    مبلغ کل    ۸٬۴۱۵٬۰۰۰
```

- عدد خط‌خورده = **عددی که در سند چاپ شده بود**؛ عدد کنار آن = عدد درست.
- دکمهٔ **نمای متن** جدول را با متن عوض می‌کند و برعکس.
- دکمهٔ **متن پاک‌شده** متن یکدست‌شده را در کادر می‌گذارد — آمادهٔ کپی در اکسل.

### موتور چه کارهایی می‌کند

| دسته | نمونه |
|---|---|
| نویسه | `ي`→`ی`، `ك`→`ک`، حذف اعراب، ارقام فارسی → لاتین |
| عدد | `۴۵۰٬۰۰۰` و `450,000` و `4500000` → یک شکل، `(1,200)` = منفی |
| جدول | شکستن با Tab / دو فاصله / `|`، تشخیص سرستون، تحمل جابه‌جایی ستون‌ها |
| قلم | شرح، تعداد، واحد، قیمت واحد، تخفیف، مبلغ — حتی بدون سرستون |
| عددی | اگر تعداد × قیمت ≠ مبلغ، **اصلاح می‌کند و می‌گوید چرا** |
| فراداده | تاریخ شمسی/میلادی، شمارهٔ فاکتور، تومان/ریال، نرخ مالیات |
| کیفیت | نمرهٔ A/B/C/D با توصیهٔ عملی |
| متن | حذف سرصفحهٔ تکراری، «صفحه ۲ از ۵»، سطرهای شکسته و تکراری |

فهرست کامل ۹۰ کار: **`docs/ENGINE-90-FA.md`**

### تنظیم‌ها (اختیاری)

در `fk-config.json` می‌توانید اضافه کنید — اگر نگذارید، پیش‌فرض‌ها کار می‌کنند:

```json
{
  "autofix": true
}
```

`autofix: false` یعنی «عدد چاپ‌شده در سند را دست نزن، فقط اشکال را گزارش کن» —
برای حسابداری که باید عین سند را ثبت کند.

### بدون mbstring هم کار می‌کند

بسیاری از نصب‌های WAMP افزونهٔ `mbstring` را ندارند. موتور از توابع `preg`
استفاده می‌کند و به `mbstring` وابسته نیست. روی PHP 7.4 تا 8.4 تست شده.

### اگر کلید کار نکرد

| پیام | معنی |
|---|---|
| «کلید معتبر نیست یا اجازهٔ دسترسی ندارد» | کلید اشتباه است یا محدودیت دامنه/IP دارد |
| «سهمیهٔ رایگان تمام شده» | سهمیهٔ روزانه پر شده؛ فردا یا با کلید دیگر |
| «درخواست رد شد» | کلید یا تنظیمات ناقص است |
| «ارتباط برقرار نشد» | سرور به اینترنت بین‌الملل دسترسی ندارد |

## اگر صفحه «سفید» است (نه چرخان)

۱. `check.php` را باز کنید: `http://localhost/faktorkhan/check.php` — می‌گوید چه چیزی کم است.
۲. اگر خطای ۵۰۰ داد، فایل `.htaccess` را موقتاً به `.htaccess.bak` تغییر نام دهید
   (برنامه بدون آن هم کار می‌کند؛ فقط فایل تنظیمات باید محافظت شود).
۳. در `php.ini` موقتاً `display_errors = On` و `error_reporting = E_ALL` بگذارید تا خطا دیده شود.

## اگر پیام «مرورگر شما به‌روز نیست» می‌آید

**این پیام دیگر وجود ندارد** — در نسخهٔ فعلی حذف شد. اگر نسخهٔ قدیمی دارید،
به‌روزرسانی کنید.

علت باگ (برای ثبت در تاریخ): برنامه برای «آزمودن» جاوااسکریپت از `new Function`
استفاده می‌کرد، ولی سیاست امنیتی خودِ برنامه (`script-src 'self'`) اجرای کد از
رشته را ممنوع می‌کند. نتیجه این بود که مرورگر `new Function` را مسدود می‌کرد،
برنامه آن را «مرورگر قدیمی» تفسیر می‌کرد و صفحهٔ هشدار تمام‌صفحه نشان می‌داد —
**حتی روی کروم تازه‌به‌روزرسانی‌شده**. آپدیت مرورگر هم فایده نداشت، چون مشکل از
مرورگر نبود.

اگر باز هم چیز عجیبی دیدید، صفحهٔ **`/browser-check`** را باز کنید. خودش می‌گوید
کدام قابلیت مرورگر موجود نیست و چه تنظیمی مانع است — بدون حدس و بدون آپدیت بی‌فایده.

## اگر ورود «یادش نمی‌ماند» و به صفحهٔ ورود برمی‌گردد

پوشهٔ سشن PHP قابل نوشتن نبوده است. از نسخهٔ ۱.۰.۱ برنامه خودش پوشهٔ `fk-sessions` را
می‌سازد. اگر باز هم مشکل بود، در `php.ini` مقدار `session.save_path` را به مسیری
مثل `C:\wamp64\tmp` تغییر دهید و پوشه را بسازید.

| پیام | راه‌حل |
|---|---|
| «افزونهٔ curl در PHP فعال نیست» | گام ۲ بالا؛ Apache را ری‌استارت کنید |
| «نسخهٔ PHP ... حداقل 7.4 لازم است» | WAMP را به PHP 7.4/8.x تغییر دهید (آیکن → PHP → Version) |

| **«سرور توکن فایل برنگرداند» (مرحله addfile)** | اول صفحهٔ `diag.php` را باز کنید و «اجرای آزمون» را بزنید؛ چهار روش ارسال فایل را با پاسخ خام سرور نشان می‌دهد. اگر همه «توکن برنشت» دادند، در `fk-config.json` مقدار `upload_method` را به `base64` تغییر دهید |
| «اعتبار سرویس ابری کافی نیست» | حساب را شارژ کنید |
| «پاسخ نامعتبر از سرویس ابری» | معمولاً خطای ۴۰۴/۵۰۰ سرور؛ فایل کوچک‌تر امتحان کنید |
| صفحه سفید | در php.ini موقتاً `display_errors = On` کنید و دوباره باز کنید |

## این نسخه چه دارد؟

**همان برنامهٔ پایتون است.** یک رابط، دو بک‌اند: همان ظاهر، همان نُه بخش،
همان ۱۲۰ قابلیت — فقط موتور اجرا PHP است. هر کاری در نسخهٔ پایتون هست،
این‌جا هم هست.

**نُه بخش:**

| بخش | چه دارد |
|---|---|
| داشبورد | کارت‌های آماری، روند مبالغ، فاکتورهای اخیر، ترکیب اسناد، دسترسی سریع |
| خوانش | آپلود/لینک، دو موتور (ابری و لوکال)، نوار پیشرفت، متن قابل ویرایش |
| فاکتورها | جدول اقلام قابل ویرایش، جست‌وجو، فیلتر، خروجی CSV/Excel/JSON، چاپ |
| گزارش‌ها | آمار ماهانه، تفکیک نوع و منبع، بیشترین فروشندگان، میانگین اعتماد |
| اشتراک | طرح‌ها، سهمیهٔ صفحه، روزهای باقی‌مانده، وارد کردن کد اشتراک |
| قابلیت‌ها | همهٔ ۱۲۰ قابلیت در ۹ گروه |
| پشتیبانی | ارسال پیام و پیگیری پاسخ |
| تنظیمات | پروفایل، تغییر رمز، دستگاه‌ها، اعلان‌ها، ظاهر |
| مدیریت | نمای کلی، کاربران، طرح‌ها، کدهای اشتراک، سرویس ابری، تنظیمات، پشتیبانی، رویدادها |

**چند کاربر و اشتراک:**

- ثبت‌نام و ورود واقعی؛ نقش‌ها: مالک (owner) / مدیر (admin) / کاربر (user)
- **جداسازی کامل داده** — هر کاربر فقط فاکتورهای خودش را می‌بیند
- کد اشتراک: ساخت گروهی توسط مدیر، مصرف یک‌باره، تمدید روی پایان فعلی،
  افزودن سهمیهٔ صفحه، محدودیت تعداد دستگاه
- چهار طرح پیش‌فرض؛ مدیر می‌تواند طرح بسازد و قیمت را عوض کند
- گزارش رویداد (audit) کامل: ورود، ساخت/ویرایش/حذف، فعال‌سازی کد
- پشتیبان‌گیری از پنل مدیریت به‌صورت یک فایل JSON (بدون رمزهای عبور)

**ندارد** (عمداً):

- پایگاه دادهٔ MySQL — همه‌چیز روی فایل JSON در `fk-data/` است.
  پشتیبان‌گیری = کپی پوشه. برای WAMP قدیمی و ویندوز ۷ همین بهتر است.
- سرویس‌ورکر/PWA — عمداً ساخته نمی‌شود تا باگ «کش قدیمی بعد از آپدیت»
  پیش نیاید.

## بایگانی فاکتور (چطور کار می‌کند)

قبلاً این نسخه فقط «خوانش» بود: متن را می‌دیدید و تمام. حالا:

1. فایل را در **خوانش فاکتور** بفرستید.
2. وقتی نتیجه آمد، پایین جدول اقلام دکمهٔ **«ثبت در بایگانی»** را بزنید.
3. فرم کوتاهی باز می‌شود که از خروجی خوانش پر شده است (شماره، تاریخ،
   فروشنده، خریدار، جمع‌ها). اقلام جدول هم مرجع‌اند؛ اگر چیزی را در جدول
   ویرایش کرده باشید، همان ذخیره می‌شود.
4. در **بایگانی فاکتورها** فهرست، جست‌وجو، مرتب‌سازی و خروجی CSV دارید.

هر فاکتور یک فایل در `fk-invoices/` است. نام فایل شناسهٔ تصادفی است، نه
شمارهٔ فاکتور — تا از روی نام فایل کسی نتواند فاکتور دیگری را حدس بزند.
مالکیت هم روی خود فایل ثبت است؛ سیستمی که مالکش نیست، آن را نمی‌بیند.

**پشتیبان‌گیری:** پوشهٔ `fk-invoices` را کپی کنید. همین.
**مهاجرت:** همان پوشه را در نصب جدید بریزید — فایل‌ها JSON ساده‌اند و
وابسته به هیچ پایگاه داده‌ای نیستند.

## «تشخیص خودکار» یعنی چه؟

در فرم خوانش، کنار «نوع فاکتور» پنج گزینه هست:

| گزینه | چه می‌کند |
| --- | --- |
| چاپی / تایپی | پیش‌فرض. جدول ستون‌دار با سرستون را می‌خواند |
| حرارتی (صندوق فروش) | فیش باریک و بلند؛ سطرها کوتاه‌اند و سرستون ندارند |
| دست‌نویس | متن نویزی و سطرهای شکسته را به هم می‌چسباند |
| صوتی | ستون‌بندی را خاموش می‌کند؛ هر سطر یک جملهٔ گفتاری است |
| **تشخیص خودکار** | خودش از نشانه‌های متن نوع را می‌فهمد و همان پارامترها را به کار می‌برد |

تفاوت با نسخهٔ قبل: قبلاً هر گزینه‌ای انتخاب می‌کردید، موتور همان مسیر
«چاپی» را می‌رفت. حالا انتخاب واقعاً روی خوانش اثر دارد:

- در **دست‌نویس**، سطرهای شکسته به هم می‌چسبند تا یک قلم کامل شود.
- در **حرارتی**، سطرهای کوتاه فیش دست‌نخورده می‌مانند (قبلاً اشتباهاً به هم
  چسبانده می‌شدند و دو قلم با هم قاطی می‌شد).
- در **صوتی**، ستون‌بندی غیرفعال می‌شود تا شماره و توضیح در یک جمله بمانند.
- در **تشخیص خودکار**، برنامه اول متن را می‌خواند و می‌گوید چه نوعی است
  (با درصد اطمینان) و بعد همان خط لوله را اجرا می‌کند.

اگر نوع فاکتور را می‌دانید، **دستی انتخاب کنید**؛ دقیق‌تر و کمی سریع‌تر
است. «تشخیص خودکار» برای فاکتورهای ناشناس و وقتی نمی‌دانید با چه چیزی
طرف هستید مناسب است.

## اگر صفحه بایگانی خالی است ولی فاکتور خوانده‌اید

دلیل: خوانش و بایگانی دو مرحله‌اند. خواندن متن به‌معنی ثبت فاکتور نیست.

- نتیجه را دیدید؟ دکمهٔ **«ثبت در بایگانی»** را بزنید.
- دکمه را ندیدید؟ یعنی کار هنوز `done` نشده یا موتور فهم قلمی پیدا نکرده
  است. در تاریخچه، دکمهٔ «نمایش» آن کار را بزنید و ببینید پیامش چیست.
- ثبت کردید و باز خالی است؟ دسترسی نوشتن پوشهٔ `fk-invoices` را بررسی
  کنید (روی ویندوز معمولاً خودکار حل می‌شود؛ روی هاست اشتراکی باید
  پوشه را قابل نوشتن کند).

## فایل `fk-owner` را پاک نکنید

این فایل یک رشتهٔ تصادفی ۳۲ نویسه‌ای است که «مالک» این نصب را مشخص
می‌کند. فاکتورهای بایگانی به این شناسه گره خورده‌اند:

- پاکش کنید → بایگانی خالی به نظر می‌رسد (فایل‌ها هستند، ولی مالک
  دیگری دارند و نمایش داده نمی‌شوند).
- کپی‌اش کنید در نصب دوم → آن نصب هم فاکتورهای همین نصب را می‌بیند.

پس در پشتیبان، هم `fk-invoices` و هم `fk-owner` را بردارید.

## نکتهٔ امنیتی مهم

اگر این پوشه را روی **اینترنت** می‌گذارید:

1. حتماً HTTPS داشته باشید (و در `.htaccess` خط HSTS را فعال کنید)
2. گذرواژهٔ محلی را قوی بگذارید
3. بهتر است به‌جای `http://site/faktorkhan/` از مسیر مخفی استفاده کنید
4. بعد از تست، فایل را بردارید — این نسخه برای تولید (production) نیست
