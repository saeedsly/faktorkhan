## شروع سریع

### الف) اجرا روی ویندوز (ساده‌ترین راه)

۱. پایتون 3.12 یا 3.13 یا 3.14 را از `python.org` نصب کنید (تیک **Add python.exe to PATH**).
۲. فایل پروژه را از حالت فشرده خارج کنید.
۳. روی فایل **`START-WINDOWS.bat`** دوبار کلیک کنید.

همین. اسکریپت خودش محیط اجرا می‌سازد، کتابخانه‌ها را نصب می‌کند و برنامه را روی
`http://127.0.0.1:8000` باز می‌کند.

> راهنمای کامل و مرحله‌به‌مرحله در سه مسیر نصب: [docs/INSTALL-FA.md](docs/INSTALL-FA.md)

در اولین اجرا یک حساب مالک ساخته می‌شود و اطلاعات ورود آن در فایل
`storage/OWNER-CREDENTIALS.txt` ذخیره می‌شود.

**اگر اینترنت ندارید یا مرحله نصب کتابخانه‌ها با خطا متوقف شد** (`Read timed out` /
`No matching distribution found`): از **بسته کامل ویندوز**
`faktorkhan-1.0.0-WINDOWS-PORTABLE.zip` استفاده کنید. این بسته خودِ پایتون ۳.۱۳
و همه کتابخانه‌ها را داخل خود دارد؛ فقط زیپ را باز کنید و
`START-WINDOWS.bat` را اجرا کنید — نه پایتون لازم است، نه pip، نه اینترنت.
جزئیات: [docs/OFFLINE-INSTALL-FA.md](docs/OFFLINE-INSTALL-FA.md)

بستهٔ کامل ویندوز شامل خودِ مفسر **CPython 3.13** (نسخهٔ رسمی Embedded، مجوز PSF) و
کتابخانه‌های از پیش نصب‌شده است؛ فایل مجوز در `python/LICENSE.txt` داخل همان بسته موجود است.

برای ساخت مجدد پوشه `wheels` روی هر سیستم با اینترنت سالم:

```bat
tools\prepare-wheels.bat
```

برای ساخت **نصب‌کننده ویندوز** (فایل Setup با صفحه حق معنوی):

```bat
cd desktop
build_windows.bat
ISCC installer\faktorkhan.iss
```

### الف-۲) چند کاربر / شبکه / اینترنت (WAMP + MySQL)

روی **`SETUP-MYSQL-WINDOWS.bat`** دوبار کلیک کنید (MySQL باید روشن باشد) و پرسش‌ها را
با Enter رد کنید؛ سپس **`START-SERVER-WINDOWS.bat`** را اجرا کنید.

این دو اسکریپت به‌طور خودکار: پایگاه داده و کاربر اختصاصی MySQL را می‌سازند،
کلیدهای امنیتی تصادفی می‌سازند، `.env` را تنظیم می‌کنند، پورت را در فایروال باز
می‌کنند و برنامه را روی شبکه اجرا می‌کنند.

راهنمای کامل سه سناریو (تک‌کاربره / شبکه محلی / اینترنت با HTTPS):
[docs/DEPLOY-WINDOWS-WAMP.md](docs/DEPLOY-WINDOWS-WAMP.md)
· چک‌لیست امنیتی برای انتشار اینترنتی: [docs/SECURITY-FA.md](docs/SECURITY-FA.md)

### ب) اجرا روی سرور با MySQL

```bash
# ۱) پایگاه داده
mysql -u root -p -e "CREATE DATABASE faktorkhan CHARACTER SET utf8mb4 COLLATE utf8mb4_persian_ci;"

# ۲) برنامه
cd faktorkhan
python3 -m venv venv && source venv/bin/activate
pip install -r backend/requirements.txt

cp backend/.env.example .env
# داخل .env این‌ها را پر کنید: SECRET_KEY، ENCRYPTION_KEY، DATABASE_URL، CLOUD_OCR_GATEWAY

python backend/run.py --host 0.0.0.0 --port 8000
```

نمونه `DATABASE_URL` برای WAMP:

```env
DATABASE_URL=mysql+pymysql://root:رمز@127.0.0.1:3306/faktorkhan?charset=utf8mb4
```

### ج) داکر

```bash
cd deploy
cp .env.example .env      # SECRET_KEY و ENCRYPTION_KEY را پر کنید
docker compose up -d --build
```

معماری داکر: `app` (FastAPI + رابط کاربری) + `db` (MariaDB) + `nginx` (اختیاری، با `--profile proxy`).

```
│                    FastAPI  (backend/app)                        │

│        │            │            │                 │             │
│  ┌─────▼────────────▼────────────▼──────────┐  ┌───▼──────────┐  │
│  │ services: parser · exporter · jobs       │  │ امنیت: JWT   │  │
│  │           local_ocr · cloud_ocr          │  │ هش رمز، قفل  │  │
│  └─────┬──────────────────────┬─────────────┘  │ رمزنگاری توکن│  │
└────────┼──────────────────────┼────────────────└───┬──────────┘  │
         │                      │                    │             │
   ┌─────▼──────┐        ┌──────▼───────┐    ┌───────▼──────┐      │
   │  SQLite /  │        │ موتور لوکال  │    │ درگاه ابری   │      │
   │  MySQL     │        │ pypdf/Tess.  │    │ (فقط سرور)   │      │
   └────────────┘        └──────────────┘    └──────────────┘      │
```

**چرا این معماری؟**

- **یک سرویس، یک فرمان:** کل برنامه یک پروسه Python است؛ روی یک سرور ساده یا WAMP بالا می‌آید.
- **بدون build برای رابط کاربری:** فایل‌های HTML/CSS/JS مستقیم سرو می‌شوند؛ نصب npm لازم نیست.
- **دو موتور OCR پشت یک رابط:** کاربر فقط «ابر» یا «لوکال» را انتخاب می‌کند؛ منطق پیچیده سمت سرور است.
- **همه تماس‌های ابری از سمت سرور:** توکن هرگز به مرورگر نمی‌رسد.

جزئیات کامل: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## سرویس ابری و مخفی‌سازی توکن

توکن سرویس ابری **در هیچ صفحه‌ای نمایش داده نمی‌شود**؛ نه در رابط کاربری، نه در پاسخ API،
نه در لاگ‌ها. مسیر امن آن این است:

1. آدرس درگاه فقط در متغیر محیطی سرور قرار می‌گیرد:

   ```env
   CLOUD_OCR_GATEWAY=<آدرس درگاه>
   ```

   این مقدار در هیچ پاسخ API برگردانده نمی‌شود و در پنل مدیریت هم نمایش داده نمی‌شود.

2. توکن را یک‌بار از **پنل مدیریت → سرویس ابری** وارد می‌کنید. توکن با کلید `ENCRYPTION_KEY`
   رمزنگاری (Fernet) و در پایگاه داده ذخیره می‌شود.

3. از آن پس فقط این‌ها دیده می‌شود: «توکن ثبت شده / ثبت نشده»، طول توکن و یک اثر انگشت
   مخفی مثل `••••••••••••abcd`. مقدار واقعی قابل بازیابی نیست و فقط **جایگزینی** ممکن است.

4. فایل پس از پردازش، از سرور ابری حذف می‌شود (قابل تنظیم در فرم خوانش).

5. در کد، تابع `_scrub()` هر ردی از توکن را از پیام‌های خطا و لاگ حذف می‌کند.

> اگر توکن لو رفت، فقط کافی است از پنل مدیریت توکن جدید ثبت کنید — بدون توقف سرویس.

## اشتراک‌سازی و کد فعال‌سازی

جریان کار پیشنهادی:

```
مدیر: طرح «حرفه‌ای یک‌ساله» → ساخت N کد → دادن هر کد به یک مشتری
مشتری: ثبت‌نام → بخش «اشتراک من» → وارد کردن کد → فعال‌سازی ۳۶۵ روزه
```

- قالب کد: `FK-XXXX-XXXX-XXXX-XXXX-CC` (رقم کنترلی ضد جعل، یک‌بارمصرف)
- هر کد فقط **یک‌بار** قابل استفاده است؛ تمدید با کد جدید انجام می‌شود و به روزهای باقی‌مانده **اضافه** می‌شود.
- هر طرح تعیین می‌کند: مدت، سهمیه صفحات، مدت پشتیبانی، تعداد دستگاه و قیمت.
- پس از پایان اعتبار یا سهمیه، API با کد `402` و پیام فارسی پاسخ می‌دهد.

راهنمای عملی فروش و پشتیبانی: [docs/OWNER-GUIDE.md](docs/OWNER-GUIDE.md)

## حریم خصوصی و امنیت

- رمز عبور با **PBKDF2-SHA256** هش می‌شود (هیچ‌گاه قابل بازگشت نیست).
- دسترسی با **JWT** و انقضای قابل تنظیم؛ قفل حساب پس از تلاش‌های ناموفق.
- محدودیت نرخ درخواست روی ورود، ثبت‌نام، بارگذاری و پشتیبانی.
- کنترل دسترسی نقش‌محور (`owner`, `admin`, `user`) در تمام مسیرها.
- بارگذاری فایل با بررسی قالب و حجم؛ ذخیره در پوشه اختصاصی هر کاربر.
- تمام درخواست‌های ابری از سرور انجام می‌شود؛ مرورگر هیچ‌گاه توکن یا آدرس درگاه را نمی‌بیند.
- گزارش رویداد (ورود، تغییر رمز، ویرایش کاربر، ابطال کد، پشتیبان‌گیری) با آی‌پی و زمان.
- هدرهای امنیتی: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store` برای API.
