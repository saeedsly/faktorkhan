# تست‌های نسخهٔ PHP

اجرای همه:

```bash
npm install php-wasm      # یک بار
node tools/tests/php/run-all.mjs
```

## چرا php-wasm؟

روی ماشین توسعه PHP نصب نیست و نصب XAMPP برای تست خودکار سنگین است.
`php-wasm` یک PHP کامل کامپایل‌شده به WebAssembly است: بدون نصب، با
همان سینتکس و توابع PHP ۸. کل تست‌ها در چند ثانیه اجرا می‌شوند.

## محدودیتی که یک بار ما را گول زد

**`php-wasm` هنگام `exit` تابع `register_shutdown_function` را اجرا
نمی‌کند.** نسخهٔ اول `harness.mjs` برای برگرداندن وضعیت فایل‌ها به این
تابع تکیه می‌کرد؛ نتیجه این بود که `state` همیشه خالی برمی‌گشت و تست‌ها
«کار پیدا نشد» می‌دادند — در حالی که کد سالم بود و فقط ابزار تست خطا
داشت.

رفع: `json_out()` در `index.php` قبل از `exit` تابع `__fk_dump()` را
صدا می‌زند. `harness.mjs` این صدا زدن را با `str_replace` تزریق می‌کند،
پس کد تولیدی آلوده نمی‌شود.

اگر تست جدیدی نوشتید و `state` خالی آمد، اول همین را بررسی کنید.

## نکتهٔ دوم: نشست را بازنویسی نکنید

`$_SESSION['jobs']` همان چیزی است که مالکیت کارها را ثابت می‌کند. اگر
در چیدمان state تست بنویسید:

```js
{ ...r.state, "fk-sessions/sess_X": 'auth|b:1;csrf|s:1:"C";' }
```

فهرست `jobs` را پاک کرده‌اید و همهٔ تست‌ها «کار پیدا نشد» می‌گیرند —
در حالی که کد درست است. از الگوی `{ ...r.state, "fk-config.json": CFG }`
استفاده کنید تا نشستِ برگشتی دست‌نخورده بماند.

## فایل‌ها

| فایل | چه چیزی را تضمین می‌کند |
|---|---|
| `reap.mjs` | کار نیمه‌کاره بسته می‌شود، کار تازه دست نمی‌خورد |
| `loginlim.mjs` | بعد از ۸ تلاش ناموفق مسدود؛ ورود موفق شمارنده را صفر می‌کند |
| `isolation.mjs` | کاربر دیگر نمی‌تواند کار دیگری را بخواند/حذف کند |
| `hist5.mjs` | تاریخچه، آمار، جستجو و CSV درست کار می‌کنند |
| `checkinv.mjs` | `checkconvert` هرگز روی تصویر صدا زده نمی‌شود |
| `invtest.mjs` | `InvalidParams` کار را نمی‌کشد؛ با پارامتر کمتر دوباره تلاش می‌شود |
| `e2e2.mjs` | چرخهٔ کامل: آپلود → addfile → convert → دانلود → متن |
| `e2e3.mjs` | قطعی شبکه، خطای اعتبار، روش نامعتبر، نشت توکن |
| `e2e5.mjs` | خروجی خالی، شکست صریح، پاک‌سازی فایل‌ها |
| `engtest*.mjs` | موتور پاک‌سازی متن و استخراج اقلام |
